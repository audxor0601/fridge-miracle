# 냉장고의기적 2.0

냉장고 재고를 등록해두면, 유통기한이 급한 재료부터 소비하도록 실제 레시피를 추천하고 상하기 전에 알려주는 웹 서비스.

## 왜 2.0인가

1.0은 학교 과제로 만든 설계서 검토용 프로토타입이었다. 화면에는 "Random Forest 정확도 88.4%"가 떠 있었지만 실제로는 `Math.random()`이 만든 숫자였고, 데이터는 상수 4건에 새로고침하면 사라졌다.

2.0의 목표는 기능 추가가 아니라 **화면에 표시된 것과 실제 동작이 일치하는 서비스**를 만드는 것이다.

| | 1.0 | 2.0 |
|---|---|---|
| 데이터 | 상수 4건, 새로고침 시 소멸 | Supabase Postgres |
| 레시피 | 하드코딩 배열 | 식약처 공공 API 수집·정제 |
| 추천 | `Math.random()` | 규칙 기반 + 유통기한 가중치 (설명 가능) |
| 사용자 | 없음 | 이메일 인증 + RLS 격리 |
| 성능 지표 | 지어낸 수치 | 실측치만 게시 |

## 기술 스택

- **프론트**: React 19, Vite, TypeScript, Tailwind CSS v4
- **백엔드**: Supabase (Postgres, Auth, RLS, Edge Functions)
- **데이터 수집**: Python (식약처 조리식품 레시피 DB, COOKRCP01)
- **배포**: Vercel

## 추천 점수 공식

```
urgency(i)      = 1 / (남은일수 + 1)
coverage(r)     = 보유한 필수재료 수 / 레시피 필수재료 수
urgency_norm(r) = min(Σ urgency(보유재료) / 필수재료 수, 1)

score(r) = 100 × (0.65 × coverage + 0.35 × urgency_norm)
```

커버리지 50% 미만은 추천에서 제외한다. 가중치 0.65 / 0.35는 실제 재고로 검증하며 조정한다.

## 막혔던 문제와 해결

<!-- 초안 상태. 실제 겪은 감각에 맞게 직접 다듬을 것. -->

### 1. 테스트는 전부 통과했는데, 사실 아무것도 검사하지 않고 있었다

RLS 정책을 적용하고 로컬 Postgres에 사용자 두 명을 만들어 격리를 확인했는데, 만든 시나리오가 하나도 빠짐없이 통과로 나왔다. 그중 "B가 A의 재고를 조회"까지 통과라는 게 걸렸다. 차단돼야 맞는 항목이었다.

출력을 위에서부터 다시 읽으니 `WARNING: SET LOCAL can only be used in transaction blocks`가 있었다. `set local role authenticated`는 트랜잭션 밖에서 무시되기 때문에 모든 쿼리가 superuser 권한으로 돌아갔고, superuser는 애초에 RLS를 건너뛴다. 검사가 통과한 게 아니라 검사 자체가 없었다.

시나리오를 하나씩 `begin; ... commit;`으로 감싸고 다시 돌리자 그제야 차단이 걸렸다. 그 뒤로는 통과 표시를 믿기 전에 실패해야 할 케이스가 실제로 실패하는지부터 본다.

### 2. 파서가 생선살을 "선살"로 만들었다

"다진", "채썬" 같은 조리 상태 수식어를 재료명에서 떼는 규칙을 만들면서 "생"도 목록에 넣었다. 생새우와 생고기를 새우, 고기로 합칠 생각이었다.

무작위 30건을 뽑아 원문과 파싱 결과를 나란히 놓은 표를 만들었더니 첫 레시피부터 `생선살(100g)`이 선살로 들어가 있었다. 생강은 강, 생크림은 크림.

같은 표에서 두 개가 더 나왔다. 재료명이 두 글자 이상이어야 한다는 조건 탓에 물, 무, 배, 쌀이 통째로 사라졌고, `물 300ml(1½컵, 200g)`처럼 괄호 안에 쉼표가 있으면 항목이 중간에서 잘려 `120g)` 같은 조각만 남았다.

한 글자 재료는 에러도 안 나고 조용히 빠진다. 최종 결과만 봤으면 셋 다 놓쳤다.

### 3. 리눅스에서 설치한 node_modules를 맥에서 쓸 수 없었다

`npm run dev`를 실행하니 `Cannot find module '@rolldown/binding-darwin-arm64'`. 패키지는 분명히 설치돼 있는데 없다고 했다.

Vite와 Tailwind는 속도를 위해 OS별로 컴파일된 실행 파일을 같이 설치하는데, `npm install`을 리눅스 환경에서 돌린 탓에 리눅스용 바이너리만 깔려 있었다. 자바스크립트 패키지라도 이런 것들은 OS를 가린다. `node_modules`와 `package-lock.json`을 지우고 맥에서 다시 설치하니 바로 떴다. `node_modules`가 왜 `.gitignore`에 들어가는지 이때 알았고, 맥과 윈도우를 오가는 프로젝트라 저장소를 옮길 때마다 새로 설치하는 걸 규칙으로 잡았다.
